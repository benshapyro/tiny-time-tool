# Dependency allowlist for tiny-time-tool.
#
# Zero-network mechanism (b) (BUILD_SPEC Constraints): CI fails
# (scripts/check-deps-allowlist.mjs) if package-lock.json or
# src-tauri/Cargo.lock gains any dependency name not listed below. A new
# dependency requires a human-reviewed allowlist change in the same PR;
# no crate/package providing network I/O is knowingly added.
#
# NOTE on "reqwest" in the cargo section: it is a transitive dependency of
# the tauri core crate itself (tauri -> reqwest), used by Tauri's mobile
# platform bridge. "cargo tree -i reqwest" against this project's actual
# host build target resolves to nothing; it only appears under
# "cargo tree --target all -i reqwest" — i.e. it is never compiled into our
# macOS/Windows desktop binaries. It is listed here because Cargo.lock
# records the dependency graph across every target Tauri supports, not just
# the ones we build for; it was not chosen or added by this project. See
# the S1 report for the verified cargo-tree evidence.
#
# NOTE on S2's `tauri-plugin-sql` addition (npm `@tauri-apps/plugin-sql`,
# cargo `tauri-plugin-sql`, feature = "sqlite" only): the plugin's Cargo.toml
# declares optional `mysql`/`postgres` sqlx backends we never enable, but
# Cargo.lock still records their full dependency closures (same "recorded,
# not built" pattern as reqwest above). Verified with `cargo tree -i
# sqlx-mysql` / `cargo tree -i sqlx-postgres` against this project's actual
# build: both print "nothing to print" — neither is in our real dependency
# graph. Their transitive crypto/auth deps (ahash, base64ct, bitvec, borsh*,
# bytecheck*, cfg_aliases, const-oid, der, etcetera, funty, hkdf, hmac, home,
# lazy_static, libm, md-5, num-bigint-dig, num-integer, num-iter,
# pem-rfc7468, pkcs1, pkcs8, plain, ppv-lite86, ptr_meta*, radium, rand*,
# rend, rkyv*, rsa, seahash, sha1, signature, simdutf8, spki, stringprep,
# subtle, tap, unicode-bidi, unicode-normalization, unicode-properties,
# wasite, whoami, wyz, zerocopy*, zeroize) are listed for the same reason:
# present in the lockfile's full resolved graph, absent from the compiled
# binary. `sqlx-sqlite` (the backend we do use) IS in the real tree, verified
# with `cargo tree -i sqlx-sqlite`.
#
# NOTE on S3's `tauri-plugin-global-shortcut` addition (npm
# `@tauri-apps/plugin-global-shortcut`, cargo `tauri-plugin-global-shortcut`
# + its direct dependency `global-hotkey`): both ARE in the real dependency
# graph for macOS and Windows (verified with `cargo tree -i global-hotkey`
# and `cargo tree -i tauri-plugin-global-shortcut` against
# `aarch64-apple-darwin` and `x86_64-pc-windows-msvc`). `global-hotkey`
# itself pulls in Linux-only X11 plumbing (`gethostname`, `x11rb`,
# `x11rb-protocol`, `xkeysym`) that Cargo.lock records across every target
# the crate supports, same "recorded, not built" pattern as reqwest above.
# Verified absent from both real shipping targets with `cargo tree -i
# gethostname` / `-i x11rb` / `-i x11rb-protocol` / `-i xkeysym` against
# `aarch64-apple-darwin` and `x86_64-pc-windows-msvc`: all four print
# "nothing to print" against both. (`x11`/`x11-dl` were already allowlisted
# before this slice, from an earlier tray-icon-related dependency — same
# reasoning applies to them, not re-verified here.)
#
